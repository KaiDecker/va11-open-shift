# OPEN SHIFT 路线图

## 阶段 20：首个公开预览版（已完成）

- 全面更新公开文档、安装说明、贡献指南和发布清单；
- 增加可重复的自动检查与发布包审计；
- 完成全新用户安装、连续两天、保存/读档、卸载和 Steam 原版哈希验收；
- 发布 Windows x64 Preview，并邀请 Issue 和 PR。

## 阶段 21：原版风格与对话质量（已完成）

- 建立角色事实、关系和语气约束；
- 使用原版流程节奏作为结构参考，避免角色身份和语气错误；
- 增加对白自然度、重复内容和立绘连续性检查。

## 阶段 22：Agent 世界深化（已完成）

- 扩展记忆、目标、关系和跨日事件；
- 保持角色信息隔离，避免模型全知；
- 让事件对后续酒吧对白和平板内容产生可追踪影响。

阶段 22 的记忆系统使用 SQLite 内的角色私有记忆。每条记忆标记来源（亲历、听说、传闻、推断）、
可信度、可见性和归档状态；检索只返回当前角色在当前时间点可知且未归档的有限内容。旧数据库会在
启动时自动补齐字段，旧记忆按 legacy 来源读取。日志只记录角色、记忆 ID、来源、检索结果和归档数量，
不记录 API Key、提示词或完整响应。关系、目标、金钱和剧情游标仍由规则层维护，LLM 不能直接修改。

## 阶段 23：轻量安装与版本隔离（已完成）

- 不再复制完整 Steam 游戏目录；实例只保存补丁后的 `data.win`，只读资源使用 Windows 链接；
- 每个安装版本独立保存数据库、日志、配置、API Key 和 OPEN SHIFT 配套存档；原版 GameMaker 存档保持兼容；
- 安装状态记录实例 ID、补丁指纹和链接清单，升级不会误用旧实例；
- 卸载只删除当前实例及其链接，拒绝触碰 Steam 原版目录；
- 默认安装目录按 `PACKAGE_MANIFEST.json` 的版本命名为 `%LOCALAPPDATA%\OpenShift-<package_version>`；
- 同卷文件优先使用 HardLink，目录使用 Junction，跨卷文件使用 SymbolicLink；文件链接权限不足时逐个复制 EXE/DLL 并记录 `copied_file`，目录无法创建 Junction 时明确停止；
- 更新安装说明、玩家包说明和安全回退测试。
- 开发构建阶段使用 UTMT 生成 `patch/data-win.delta`；玩家端只应用带原版/目标 SHA-256
  校验的增量补丁，发行 ZIP 不包含 UTMT 或完整 `data.win`。

## 阶段 24：启动器与社区体验（已完成）

- 迁移到不携带 .NET runtime 的 Win32 + WebView2 原生宿主；
- 采用黑底、深紫硬边框和像素字体的 VA-11 HALL-A 风格启动界面；
- 增加更新检查、日志导出、一键修复和版本诊断；
- 改善生成模式、耗时和错误提示；
- 根据社区反馈迭代安装和贡献流程。

## 阶段 25：公开预览版发布准备（已完成）

- 统一公开版本号为 `v0.24.0-preview`，并准备对应的 GitHub Release 说明；
- 完成全新机器安装、API Key 保存、世界状态准备、启动、重启和卸载验收；
- 核对 GameMaker 临时运行配置路径修复，避免本地服务已启动但游戏无法读取连接信息；
- 对玩家 ZIP 做轻量包审计，确保不包含 UTMT、完整 `data.win`、源代码、数据库、API Key 或验收素材；
- 同步安装文档、发行清单和社区更新文案，明确旧 `v0.19.0-rc.23` 已过时。

## 阶段 26：持续城市事件与社区反馈（已完成）

- 建立 DAY2 至 DAY12 的代码拥有公共城市事件候选池，让每个营业日从多个城市背景中稳定抽取一个事件；
- 按世界种子、候选池版本和日期使用可复现选择，同一存档重复准备不会改变结果或重复写入；
- 保持事件键、类别、状态和关联角色经过规则校验，并让重复准备保持幂等；
- 根据实际游玩反馈继续调整事件密度、角色反应和原版风格，逐步扩展社区事件与跨日影响。

## 阶段 27：LLM 城市事件候选（已完成）

- 允许支持该能力的 provider 为每天提出最多三个公共城市事件候选；
- 候选严格通过事件键、类别、状态、文字长度和关联角色校验后才可进入世界；
- 候选、稳定选择结果和最终事件使用 SQLite 元数据与事件账本幂等保存；
- provider 不可用、返回错误或校验失败时回退到阶段 26 的代码事件池；
- 记录生成开始、结束、错误和回退耗时，不记录提示词、响应正文或密钥。

## 阶段 28：城市事件驱动对白与对话记录（进行中）

- 将当天已经持久化的公共城市事件作为只读上下文，加入角色故事和开店前对白的生成前提；
- 保持角色故事事件、剧情游标、金钱和关系等权威状态不被公共事件上下文改写；
- 生成失败时继续使用本地对白回退，且没有公共事件时保持原有行为；
- 对每个已展示场景按营业日、场景和台词顺序记录对白，使用幂等收据避免重复写入；
- 不记录 API Key、提示词全文或 provider 的原始响应，并继续保留原版音乐、休息、保存和房间切换边界。
